D-005 — Golden tests store published results, not third-party input files (2026-11-13)

  • Evidence: IEEE PES test-feeder files say "All rights reserved" with no open licence; MATPOWER excludes its case files from its BSD licence [PF-01, PF-09].
  • Decision: The repo contains (a) our own original networks, (b) short published result values with citations (facts used for comparison), and (c) where an input network from a paper is needed (e.g., Baran & Wu 33-bus line/load table), it is re-typed from the published paper as numeric data with a citation, treated as factual data — and flagged in VALIDATION.md. Raw .m/.zip/.xls files are never committed. Cross-validation with pandapower (BSD-3) happens offline/dev-only.
  • Alternatives: commit raw files (licence risk); skip published cases (loses validation).
  • Risk/uncertainty: whether numeric tables from papers are protected is a legal question we cannot settle; impact is small and reversible (remove the fixture).
  • Reversible: yes.

D-006 — Saudi parameters default to SEC public documents, labelled by edition (2026-11-13)

  • Decision: Network defaults follow SEC DPS 2004 / Grid Code 2021 / SDMS specs (13.8 kV, 60 Hz, open loop between grid stations, 50 % loading, ≤7.5 km to NOP, 3×300 Al XLPE, package substations 500/1000/1500 kVA Dyn11, RMU 400 A 21 kA 1 s). Where SEC data is not public (NER value, FPI settings, crew times, UFLS table), values are labelled assumption in Model notes, and made scenario parameters.
  • MV earthing default: low-resistance earthed (SEC has an NER spec, 57-SDMS-01) with an assumed limit chosen in FIDELITY.md; solid earthing is selectable.
  • Operational procedure (halving by customers, backfeed via NOP, re-energisation delays, duty counts) follows documented UK DNO practice (SSEN), labelled as such, because no SEC operating manual is public.
  • Reversible: yes (data tables).

D-016 — Next mode is Grading (relay chain), not Heatwave (2026-11-13)

  • Evidence: in the v1 network model, moving normally-open points does not change transformer load (each transformer serves its own customers), so a Heatwave mode would need LV load-transfer or demand-response modelling first (D3-14 observed the same). The transformer thermal engine is built and validated (VALIDATION §3b) and waits for that.
  • Grading uses only validated parts (IEC curves, short circuit) plus sourced constraints (CTI 0.25–0.4 s, inrush 12×In 100 ms, pickup above load). Fuse curves remain unsourced, so the chain uses a breaker-type RMU tee-off (SEC 32-SDMS-04).
  • Reversible: yes.

D-017 — Condition-of-the-day rotation for the daily (2026-11-13, D3-04)

  • Seven conditions cycle by UTC day: standard, solidly earthed district, heat (40 °C ground, 15:00 summer), one crew, SCADA comms trouble, stale indicators, digger strike with damage report. Each is a generator override; every condition is gated by the reference bot finishing 20/20 seeds (tests/property/nightshift.test.ts).

D-018 — Grading review fixes (2026-11-13, docs/qc/REVIEW-grading.md)

  • GR-01: margins now checked at the close-in feeder fault (busbar level: feeder vs incomer) and at the RMU tee-off side (cable-end level: tee-off vs feeder).
  • GR-02: LV-terminal faults are no longer scored for speed; the tee-off must take ≥ 0.4 s there (LV discrimination [A]) and ≤ 2 s (transformer withstand, SEC 51-SDMS-04 [V]).
  • GR-03: high-set must be ≥ 1.3 × max LV fault (no reach through the transformer).
  • GR-04/GR-12: LV minimum = LV earth fault seen as 1/√3 through Dyn11 [D]; minimum cases use 0.5 × S″k (one grid transformer out) [D].
  • GR-05: number fields commit on change, no per-keystroke clamping. GR-08: Arabic "incomer" = قاطع الوارد, bidi-isolated reference line. GR-09: score named "relay operating time". GR-11: duplicate/∞ messages fixed. GR-13/15: CT simplification and greedy (non-optimal) reference stated in the UI.
  • GR-06 partly rejected with reasons: a backup ≤ 2 s rule is enforced for MV faults; for LV-terminal faults on small transformers it is physically infeasible with inverse-time feeder relays (fault current ≈ feeder load, e.g. 445 A vs 300 A for 500 kVA), which is exactly why the tee-off breaker is the transformer's protection. Stated in-game.

D-019 — v2 player experience: guided first lesson, tiered hints, solution player, readable mimic (2026-11-20)

  • Trigger: the owner, an electrical engineer, could not work out how to play v1 and found the visuals cheap. Research: research/13-onboarding-ftue.md (FTUE, hints, solution replays), research/14-graphics.md (rendering, art direction, assets).
  • Lesson 1 (#/tutorial, src/ui/tutorial.ts): first launch goes straight into a 3-minute guided incident. One action at a time, target spotlighted, everything else softly dimmed; off-step actions are explained, not executed. Jargon (FPI, NOP, isolated) is named after the player has used it.
    • Rejected from the research note: "close the NOP first for a win in 60 s". It would re-energise the fault from the other station. The lesson keeps the safe order: read indicators → isolate both ends → re-close the breaker → close the NOP. First homes return after about 5 clicks.
  • Goal line always states the current phase (locate / isolate / restore / make safe / repair / return to normal) from the player's own evidence; it never reveals the hidden fault.
  • Tiered hints (src/ui/hints.ts): 1 where to look, 2 why (principle), 3 exact next step (may use the true fault; caps the shift at ★★), 4 watch the solution (caps at ★). Tier 3 includes sectionalising by trial closes, dead switching before a breaker trial close (P-09), damage reports first, and backfeed overload handling. Gate: following tier 3 alone finishes 120/120 seeds with zero safety star-events (tests/unit/hints.test.ts covers 36).
  • Solution player (src/ui/Demo.tsx): the reference strategy replayed like a narrated video (captions AR/EN, pause, step, 1×/2×, take over from here). Generated from the deterministic engine, so it always matches the incident. Stated limitation: it plays from the start of the incident, not from the player's current state. Demo sessions never write scores.
  • Readable mimic (NetworkView v2): glowing live cables with moving current dashes in the supply direction, homes that light or go dark, single-line switch symbols, indicator flags, trucks, a legend; custom icons replace emoji. Phones get a vertical layout. The 3D view (research/14) is phase 2.
  • Reversible: yes. Engine unchanged; replays and determinism unaffected (help use is not part of the action list).
